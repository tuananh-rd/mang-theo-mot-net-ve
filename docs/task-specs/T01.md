## Kiểm tra cần thực hiện

1. Ghi node/npm/Git và dependency versions; cài ứng dụng tối thiểu trong folder hiện có, không overwrite tài liệu. Sau khi lockfile có, `npm.cmd ci` trên Windows (hoặc npm ci ở môi trường tương đương).
2. Scripts package: `dev`, `check`, `build`, `preview`. Chạy check và build, ghi lệnh/exit code/kết quả; không chỉ báo “pass”. Nếu mạng cài bị chặn, báo lỗi chính xác, không claim build thành công.
3. Serve output build trên loopback; mở sáu URL và một URL không tồn tại. Kiểm link, reload và menu bằng trình duyệt thực tế. Kiểm 404 behavior của server local và ghi khác biệt nếu static host preview không phản ánh HTTP status phát hành.
4. Desktop 1440×1000, tablet 768×1024, mobile 375×812, zoom 100%; kiểm không tràn, ảnh/card/CTA, menu mở, Tab/Escape, reduced motion nếu có. Ghi browser/version và viewport thực tế. Nếu không dùng được browser, báo BLOCKED cho bằng chứng UI; không tạo ảnh giả hoặc coi build là visual pass.
5. Audit dist: liệt kê file, tìm DOCX/docs/source/chứng từ/contact/QR/secret/placeholder thật giả; xác nhận public/images/README.md không bị copy. Audit nội dung bằng đọc output, không chỉ đếm file.
6. Không viết test lặp copy tĩnh. Nếu có logic menu/trạng thái dữ liệu cần kiểm, dùng kiểm hành vi hoặc test đúng rủi ro. Phép tính tài chính đầy đủ thuộc T03, không làm thêm cho T01.
